# Аудит артефактов Isaac для Ёнэ

В установленном Repentance+ под REPENTOGON (игровой лог `J273`) сверили **721 ID коллекционных предметов и 188 ID тринкетов** с локальным извлечённым `items.xml`. Это инвентаризация предметов. Поддержку в бою подтверждают отдельно для конкретного эффекта и сочетания.

| Данные | Количество |
| --- | ---: |
| Пассивные предметы | 425 |
| Активные предметы | 170 |
| Фамильяры по тегу `familiar` | 126 |
| Тринкеты с записью в XML | 188 |
| Старые имена без записи в XML | 4 |

Последние ID предметов и тринкетов в установленных enum — 732 и 189. В enum тринкетов остался `TRINKET_POLAROID_OBSOLETE` (47). Старые имена `COLLECTIBLE_PILLS_HERE` (43), `COLLECTIBLE_TAROT_CARD` (61) и `COLLECTIBLE_235` встречаются только среди присваиваний для совместимости. Всего найдено 30 дополнительных имён коллекционных предметов и 2 имени тринкетов, включая три перечисленных выше. Внутренние записи `<null>`, ограничители `NUM_*`, маска ID и золотой флаг тринкетов находятся за пределами списка игровых предметов. Предмет в XML может быть скрыт или ограничен пулом либо режимом.

## Как получить таблицу по каждому ID

Запусти из корня репозитория. Укажи извлечённый `items.xml`, соответствующий используемым игровым ресурсам. В команде указан локальный путь к уже извлечённому базовому XML. При наличии патчей передай дополнительные `--items` в порядке наложения. Для локального первичного обхода достаточно `--enums`, а `--eid` добавляет подсказки по механикам из установленного External Item Descriptions.

```powershell
$isaac = 'C:/games/steamapps/common/The Binding of Isaac Rebirth'
$items = '../little-horn-afterbirth-plus/extracted_resources/resources/items.xml'
$eid = "$isaac/mods/external item descriptions_836319872/descriptions"
python tools/audit_yone_isaac_items.py --enums "$isaac/Repentogon/resources/scripts/enums.lua" `
  --items $items --eid $eid > yone-isaac-audit.tsv
```

Ключ строки — пара `registry, id`. В таблице есть основное имя enum, старые имена, тип записи, cache-флаги и признаки механик для проверки. `--summary` печатает только счётчики. Базовый XML из примера содержит все 909 актуальных ID из установленных enum. Хеш SHA-256 XML `37A8D1B2377FEEF78B5690B859ABFF23AB81B98B06F1A41C83D4392DB35FC556`. Хеш установленного enum `6EF9A12C5DA35C634C61C56162602CF797A7EB27ABBE8CC0C65E8D09EDDDA83D`.

Типы и ID берутся из локальных игровых данных. Поле `candidate_checks` — эвристика из cache-флагов и ключевых слов EID. Например, Poison может означать слезу, контакт с телом или активный эффект. Предмет без cache-флагов может менять залп. Некоторые механики меняются между версиями. `manual-review` означает, что по этим признакам нужен ручной разбор. Скрипт считывает тексты EID из `ab+`, `rep` и `rep+` и выводит только категории. Список из запущенного экземпляра можно уточнить через размеры `Isaac.GetItemConfig():GetCollectibles().Size` и `GetTrinkets().Size` и прямой вызов `GetCollectible(id)` или `GetTrinket(id)` для каждого ID. [ItemConfig](https://wofsauge.github.io/IsaacDocs/rep/ItemConfig.html) · [Поля items.xml](https://repentogon.com/xml/items.html)

Темп автоатак и КД Q используют `MaxFireDelay`. `TearRange` ограниченно масштабирует AA/Q/Q3, а Mom’s Knife дополнительно даёт +10 п.п. к множителю дальности. Предел множителя 0,85–1,35. Скорость слезы влияет на дополнительный залп. Проверять статы и геометрию зоны независимо от внешнего вида выстрела. |

## Масштаб, владение и повторные срабатывания

- Прямое попадание клинком, попадание снарядом и вторичный эффект имеют разный контекст. Передачу статуса привязывай к первому принятому удару по живому NPC и одной фактической слезе. Промах, отменённый урон, смерть от прямого удара, развёрнутая последовательность Q3 и возврат E требуют отдельных проверок. Дополнительный залп не должен добавлять второй стак Q, вторую отметку E или второй прок предмета LoL.
- Первичный бюджет слёз равен 28% базового урона для одиночного носителя или 20% на весь многозарядный залп. Перенесённые статусы получают повреждение исходного носителя, с которым их вызвал движок. Для яда, горения, взрывов, колец и ветвления измеряй итоговый урон отдельно, включая стационарные цели и несколько врагов. Нативный коэффициент самого прока может отличаться от урона носителя.
- Проверяй обычную копию, две копии и временный эффект предмета раздельно. Где важна кратность, сверяй `GetCollectibleNum` и правила конкретного предмета. Текущие ручные бонусы 20/20, Inner Eye, Mutant Spider и Mom’s Knife проверяют наличие, а слёзы используют результат нативного расчёта. Для тринкетов `GetTrinketMultiplier` учитывает золотой вариант, проглоченный тринкет и Mom’s Box. Rainbow Worm использует проверку кратности больше нуля. Сильные тринкетные эффекты требуют своей проверки кратности.
- Проверяй сочетания, где два источника дают один и тот же флаг или разные методы нанесения урона: Common Cold + Scorpio, Cricket’s Body + The Parasite, Rainbow Worm + другой Worm, многозарядность + задние и боковые выстрелы, C Section + замена оружия. Передавать общий флаг стоит один раз для каждого предусмотренного попадания. Состояние сохраняй за конкретным владельцем атаки и комнатой.

Симуляции `tools/check_yone_artifacts.py`, `tools/check_yone_artifact_weapons.py` и `tools/check_yone_combat.py` проверяют код Lua на контролируемых входах. Для проверки движком начни с AA, Q и Q3 по одной живой цели и двум целям, в том числе с промахом, смертельным первым ударом, стеной и остатком эффектов при смене комнаты. Повтори для базового предмета, пары предметов и золотого тринкета. Записывай отдельно версию игры, ID и источник урона, срабатывание, величину, задержку и число затронутых целей.
